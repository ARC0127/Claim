# Claim

![Claim — 从研究主张走到必须证明的桥梁](docs/assets/claim-cover.svg)

## 你知道想说明什么。下一步，究竟必须证明什么？

Claim 是一个专注理论判断的科研对话 skill：从你的论文主张出发，检查量词、反例和假设，帮助你亲自写出缺失的证明目标。

它最关注的不是“该用哪个定理”，而是更早的一步：**这个定理的输入和输出，真的能把你的论证接起来吗？**

[立即开始](#快速开始) · [看一个具体案例](docs/examples.md) · [使用指南](docs/guide.md) · [验证与边界](docs/validation.md)

当前版本：**0.2.0 · internal**。一个 `$claim` 入口，内置辅导、主张检查和确认后归档；核心使用不需要安装其他研究 skills。

## 为三个卡点而做

**“指标更好，所以任务更好。”**

指标、比较对象和最终结论可能不在同一个层次。Claim 检查第一条尚未成立的推理，让证明目标回到论文真正声称的结论。

**“反例出现了，再加一个假设吧。”**

新增条件可能排除了最重要的应用范围。Claim 先让你尝试提出最小条件，再检查它是否阻断反例、是否偷写了结论，以及付出了什么代价。

**“我知道要用集中不等式，但不知道要证哪一句。”**

定理名字不能代替证明目标。Claim 先检查你写出的输入、输出、定义域、保证方式和误差，再进入理论类别与已有定理的检索。

## 看见缺口，而不只是得到答案

> **研究者的尝试：**“我需要证明，我选中的方案，其估计成本接近真实成本。”
>
> **Claim 的局部反馈：**“这控制了选中方案，却没有控制被你拿来比较的其他方案。它们可能被严重高估，因此估计排名还不能说明真实排名。”
>
> **留给研究者的决定：**“为了支持你和最佳候选的比较，这条义务还需要覆盖哪些对象？”

这是原创的教学示意摘录，不是真实模型运行记录。完整案例包含可手算的反例、必要的版本修订，以及研究者自己的义务尝试；它不把“近似最优”包装成“严格更好”。[展开案例 →](docs/examples.md)

## 快速开始

需要能加载本地 skills、读取 UTF-8 文件并搜索网页的客户端。没有网页访问时，Claim 必须明确报告来源未核实，不能假装完成文献核对。

### 1. 安装完整文件夹

下载 [Claim-0.2.0.zip](dist/Claim-0.2.0.zip)，或从本仓库取得完整 `claim/` 文件夹。不要只复制 `SKILL.md`。

首次安装，Windows PowerShell：

```powershell
$claimSkillsRoot = if ($env:CODEX_HOME) {
    Join-Path $env:CODEX_HOME "skills"
} else {
    Join-Path $env:USERPROFILE ".codex\skills"
}
Expand-Archive -LiteralPath ".\dist\Claim-0.2.0.zip" -DestinationPath $claimSkillsRoot
```

macOS / Linux：

```bash
claim_skills_root="${CODEX_HOME:-$HOME/.codex}/skills"
unzip dist/Claim-0.2.0.zip -d "$claim_skills_root"
```

以上示例从仓库根执行。单独下载 ZIP 时，将命令中的 ZIP 路径换成下载位置。已有 `claim/` 时先备份，再升级；不要直接覆盖自己修改的版本。[升级与编码检查 →](docs/guide.md#安装升级与中文)

### 2. 用一句原话开始

在能读取新 skills 的对话中发送：

```text
使用 $claim 逐轮引导我，不要替我完成理论。
我希望读者相信：在……条件下，我的方法相对于……，能够……。
```

不必先知道定理名字。当前对话中你亲自写过的主张可以直接使用；跨对话找回的原话需要你重新确认。

## 同一个入口，两种不同帮助

| 你要什么 | 如何调用 | Claim 的工作 |
|---|---|---|
| 训练自己判断 | “用 $claim 引导我分析” | 每轮一个决定；假设和证明义务由你先尝试 |
| 深入理解当前概念 | “详细解释这个概念，不推进” | 在当前阶段展开解释，不替你选择答案 |
| 直接检查一段论证 | “用 $claim 检查这条主张和论证” | 检查范围、首个缺口、证据适用性，给有边界的判断 |
| 整理已确认结果 | 完成辅导后明确请求归档 | 导出当前版本，保留未知项、修订和未证明义务 |

Coaching 不会因上下文足够丰富而自动切成 Review。直接检查可以提出 AI 的证明目标，但不能倒填成“研究者已经独立完成”。

## 一条完整的思考路径

```text
你想让读者相信什么
  → 量词与比较对象到底是什么
  → 哪个有效反例能击穿它
  → 你愿意增加什么条件，牺牲什么范围
  → 第一条缺失的桥梁，需要怎样的输入—输出结论
  → 这个缺口为何成立不了，属于什么理论问题
  → 什么结果会让你承认失败
  → 确认后归档，并单独检查迁移能力
```

每轮状态可见，旧版本保留。修改上游对象或量词后，依赖它的下游判断需要重做；不能悄悄缩小主张，再把原来的失败写成成功。

## 0.2.0：把定理义务这一步做深

- **局部反馈更具体。** 对照主张和你的义务尝试，找出最影响结论的缺项，并说明它为什么重要；不一次抛出所有诊断标签。
- **反例判断更严格。** 先核对前提；没找到反例不算证明，也不为了通关编造反例。单次坏样本不能自动推翻高概率保证。
- **检查与归档内置。** 主张、短论证、证据适用性和已确认记录导出有自己的协议，不再硬跳转到外部研究 skill。
- **安装与发行可核对。** 独立 UTF-8 校验、精确文件清单、可重复构建和安装副本比较，让“仓库改了，本地却没更新”可被查出。

逐轮教学、渐进提示、详细解释、实时检索、版本回退和迁移检查来自已有版本；它们在本次被保留，不被重新计作新增功能。[版本记录 →](docs/changelog.md)

## 有依据的反对，而不是附和

每次新增或修改实质性科学内容，协议要求重新搜索相关文献。旧书目只能作线索，重新打开并核实适用性后才能继续引用。

发现冲突时，Claim 要说明反对的具体命题、来源原结论及其条件，并给出作者、标题、年份、直接链接或 DOI、适用范围和核对日期。没有找到支持，不等于你的想法是错的。公式中的每一个符号、下标与概率对象都必须解释，不能只堆英文名称。

## 哪些已经验证，哪些还没有

本仓库提供可运行的文件、编码、打包和安装一致性检查，以及待执行的教学行为场景。**文件检查通过，不等于模型必定遵守协议；共同完成一条主张，也不等于研究者已经掌握方法。**

Claim 不是自动证明器，不内置后台自治、动态 skill 自进化或完整论文生产平台。没有运行的证明、模型行为和人类学习效果，都不能被记作成功。[查看实际验证记录 →](docs/validation.md)

教学设计参考了认知学徒制的脚手架与逐步撤去支持，也参考了区分“有 AI 时的表现”和“撤去 AI 后的表现”的研究；这些是设计依据，不是 Claim 有效性的实验结果。[来源与适用边界 →](docs/design-notes.md)
