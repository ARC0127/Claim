# Handoff to a user-selected local tool

Claim works on its own. When the user requests cooperation with another local
tool, verify the actual entry they selected and read its routing instructions.
Do not discover or announce private tool names from historical context.

## Outgoing handoff

Pass the current claim version and original wording, confirmed scope and
assumptions, the user's obligation attempt and accepted revision, proof/source
status, and the exact remaining task. Distinguish review, formalization,
implementation checking and writing. Follow the selected tool's actual entry;
do not assume its capabilities from its name.

During S1-S6, keep Claim's coaching protocol in control. A handoff must not supply
the user's assumption or obligation before their attempt. Separate proof or
review work requires an explicit mode transition. Its result cannot create past
gate confirmations. S7 exports confirmed decisions unless the user separately
requests new work.

## Incoming handoff

Read Claim's entry and select coaching or review from the user's intent.
Preserve the fresh-search, formula and version rules. A summary may locate an
old claim, but it cannot replace a verbatim user statement or missing confirmation.
Return the updated claim record and unresolved obligation within the agreed task.

If the selected tool is unavailable, report that fact and use a corresponding
built-in route only when it fits the request. Keep installations separately
versioned; updating Claim does not change another tool's files.
