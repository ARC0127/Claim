# Optional cooperation with a local ZYR installation

Claim works on its own. When the user explicitly requests ZYR cooperation, verify
the actual local `zip-your-research/SKILL.md`, read its routing instructions and
choose only the relevant route. No network installation or global reconfiguration
is needed. Never infer availability solely from a past conversation.

## Claim to ZYR

Pass a compact handoff containing: claim version and original wording; confirmed
scope/quantifiers/assumptions; user's obligation attempt and accepted revision;
proof/source status; exact remaining task; and whether the user chose review,
formalization, implementation binding or writing. Then follow the installed
entry's actual route. Do not guess legacy skill names or duplicate its internals.

In S1-S6 coaching, keep Claim as the primary protocol. Cooperation must not supply
the user's assumption or obligation before their attempt. An external proof or
review request requires an explicit mode transition; its result does not fabricate
past gate confirmations. S7 remains an export of confirmed decisions unless the
user separately asks for new proof work.

## ZYR to Claim

ZYR can hand a scoped claim question to this entry when it is actually installed.
Re-read Claim, select coaching or review from user intent, and keep its fresh-search
and formula rules. An old ZYR summary can locate a claim but cannot stand in for a
verbatim user statement or missing confirmation. Return the updated claim record
and unresolved obligation, not an invented full-research completion state.

If ZYR is absent, use Claim's corresponding built-in route and report the missing
optional cooperation only when it matters to the user's request. Version each
product separately; updating Claim does not overwrite or downgrade the local ZYR.
