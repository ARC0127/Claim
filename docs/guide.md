# 使用 Claim

[返回主页](../README.md)

Claim 提供逐轮辅导、直接检查、确认后归档和独立的形式证明路线。你可以通过 CLI、Claude Code 或 Codex 使用同一套规则；[调用方法](cli.md)集中说明安装与启动。

## 从哪个模式开始

训练自己的判断时，明确说“引导我”“不要替我完成”。直接交付检查结果时，明确说“检查这条主张和论证”。含糊的“分析 claim”不能成为自动生成整套理论的授权；模型应先澄清意图。

修改 Claim 文件、检查版本、修复编码等维护请求不走辅导阶段，也不应套四段教学格式。

## 辅导中的固定格式

S1–S6 的最终回复必须使用以下四个标题，状态块紧跟第一个标题。此处展示普通 S1；其他阶段和特殊模式的合法值以[权威协议](../claim/references/theory-coach.md)为准。

```text
1. **你刚才表达了什么**

`阶段 S1 · GATE OPEN`
`模式：STANDARD`
`检索：NO_NEW_SCIENTIFIC_CONTENT`

2. **我如何形式化**

3. **当前最大歧义**

4. **一个需要你亲自回答的问题**
```

每轮只处理一个决定，唯一的问题在第四节。`OPEN` 表示当前决定尚未解决；`PASSED` 需要这一轮用户自己的明确作答满足条件。“继续”不能替代未完成的判断。

详细解释时使用 `DEEP_DIVE · NO ADVANCE`，仍保留四节，但第二节可充分展开。新科学内容触发本轮重新搜索；搜索本身不通过任何阶段。发现有来源支撑的实质冲突时进入 `EVIDENCE_CHALLENGE · NO ADVANCE`，先展示证据，再由用户决定是否修改主张。

## 每一步由谁完成

| 阶段 | 研究者的决定 | AI 的帮助 |
|---|---|---|
| S1 主张 | 对象、条件、比较对象、结论 | 忠实拆解，不补方法或偏好 |
| S2 形式化 | 确认量词与数学表达仍是原意 | 定义所有符号，不偷偷加强结论 |
| S3 反例 | 是否在范围内、是否排除、代价 | 核对前提后构造反例，不同时修复 |
| S4 假设 | 先提出最小条件，再接受或拒绝 | 检查是否阻断反例、循环论证及范围成本 |
| S5a 证明义务 | 先写需要的输入—输出桥梁 | 检查单个最大缺项，解释其影响 |
| S5b 理论类型 | 先解释失败机制，再尝试分类 | 允许复合与未知，再核对最小理论工具 |
| S6 失败规则 | 什么结果会改变自己的判断 | 检查是否真的能证伪当前版本 |
| S7 归档 | 所有前置判断确认后明确要求导出 | 只整理当前确认版本，不创造新成果 |

没找到有效反例可以如实保留不确定性，由用户决定是否有条件继续；不能捏造一个反例来满足流程。没有新增假设的合理依据时，也不能为了完成表格硬加条件。

## 卡住时如何获得帮助

可以说“详细解释这个区别，但不要给我本题答案”。解释保持在当前阶段，不改变 gate。

S4 的提示逐步增加：先指出反例利用的自由度，再用无关领域的中性例子解释，让你尝试限制它；仍表达不出时才给一个有来源标记的候选条件。AI 提供的提示不记成你的独立发现。

S5a 首先检查你已经写出的证明目标。你可以不知道定理名字，但需要说明希望证明怎样的输入—输出关系。输入、输出、量词等项目不是每题都要生造一遍：例如确定性结论不必虚构置信参数，但要说明为何不适用。

## 文献、公式与反对意见

新增主张、假设、比较对象、量词、科学解释或证据时，应重新检索，不自动继承上轮书目。纯粹确认已展示的内容、调整格式或原样导出不算新科学内容；导出时新增解释则算。

来源要能打开，并核对作者、标题、年份、DOI 或直接链接、原命题位置、条件和适用范围。模型记忆不构成反驳依据；检索失败应显式留下未核实状态。查到一个结果也不能隐瞒其他实质反证。

每个公式附近解释所有变量、函数、集合、上下标、概率或期望对应的对象与随机性；名称之外还要交代它在当前研究中指什么。具体合同见[入口](../claim/SKILL.md)。

## 修订与继续旧研究

你可以修改任何确认过的判断。旧版本、修改原因和范围成本须保留，受影响的下游阶段重新打开。透明修订是正常研究活动；隐去失败版本、偷偷更换比较对象则不是。

当前对话中的用户原话不用重复。跨对话恢复必须能找到逐字的用户消息，先标记 `UNCONFIRMED_PRIOR_USER_CLAIM`，展示后由你重新确认；AI 总结、草稿和记忆只能定位来源，不能代替原话。

记录协议只整理这条主张的决定与来源，不会自行建立全局知识库、后台学习或修改 skill。文件保存遵循宿主权限与用户的归档要求。[记录字段 →](../claim/references/claim-record.md)

## 归档与迁移分开

S1–S6 确认后，可以导出 Theory Specification、简短论证图或定理目标。尚未证明的义务仍标为未证明，`UNKNOWN` 不因排版变成已解决。

学习目标还需要相邻但不同的主张练习，依次独立识别对象、量词和第一条坏箭头。提示过的尝试如实记为受支持；一次独立通过只提供初步迁移证据，不证明全面掌握。练习不混进论文归档。

## 安装升级与中文

完整文件清单见[manifest](../manifest.json)。辅导、检查和归档内置；形式证明使用可用的 Lean 环境，本地 ZYR 则按明确请求协作。

升级时先检查现有目录是否有个人改动；将整个旧目录复制到 skills 目录之外作为备份，再把新版完整文件夹安装到原位置。保留备份，确认新版可用后再自行处理旧版。不要把两个版本混在同一 `claim/` 中。

`theory-coach.md` 使用 UTF-8 BOM，兼容 Windows PowerShell 5.1 默认读取；其余文件无 BOM，仍须显式 UTF-8 读取。两种正确读取方式：

```powershell
Get-Content -LiteralPath ".\claim\references\theory-coach.md" -Encoding UTF8
```

```python
from pathlib import Path
text = Path("claim/references/theory-coach.md").read_text(encoding="utf-8-sig")
```

发现损坏字符时应停止复制该模板、重新读文件，不能继续使用旧上下文中的乱码。磁盘更新不会改写历史消息。升级后在新会话中重新读取 Claim，避免沿用旧模板。

维护者可在仓库根执行：

```powershell
py -3 -B tools/validate.py --installed "实际的 skills/claim 路径"
py -3 -B -m unittest discover -s tests -v
py -3 -B tools/package.py --check
```

验证器要求 Python 3.10 或更新版本，无第三方包。`tools/validate-encoding.ps1` 是 Windows 兼容入口；外部宿主验证器只有显式指定时才运行，不是 Claim 的依赖。[验证边界 →](validation.md)
