# 用 Lean 与 Prove2Me 继续完成证明

[返回主页](../README.md)

当研究者已经明确“要证明什么”，Claim 可以协助组织论证、拆分引理并完成形式化。Lean 检查形式证明，Prove2Me 可组织目标和依赖，Claim 则核对形式命题与原研究主张是否一致。

## 先锁定命题，再写代码

保留当前主张版本、确认的量词与假设，以及定理义务的输入和输出。形式化前逐项解释这些对象在 Lean 中的表示。若只能证明更窄的条件，要指出改变的位置，由研究者决定是否接受。

辅导中的 S5a 仍要求研究者先提出证明义务。归档只整理已确认结果；继续写证明需要明确请求：

```text
使用 Claim 将当前确认的定理义务写成 Lean 证明。
先给出自然语言论证和形式命题对应关系，再检查证明依赖。
```

## 一条可执行的证明链

| 步骤 | 产物 | 需要回答的问题 |
|---|---|---|
| 明确义务 | 原命题与条件 | 到底需要证明哪一句 |
| 组织论证 | 定义、子引理、依赖关系 | 每个引理解决哪一步推理 |
| Lean 形式化 | 固定环境中的 `.lean` 文件 | 形式命题是否忠实表达原意 |
| 编译与公理检查 | 日志、退出码、公理列表 | 证明是否依赖占位目标或新增公理 |
| 可选 Prove2Me | 目标、子义务、提交和状态 | 哪些依赖已完成，哪些仍未证明 |
| 回查应用 | 定理前提与代码或证据对应 | 当前应用是否满足条件 |

依赖图应区分编译器提取的定理依赖、尚未证明的分解，以及实现或实验支持关系。只有第一类是形式证明中的逻辑依赖，不能把其他边也画成已成立的蕴含。

## 运行基础算术示例

[ClaimDemo.lean](../claim/assets/proof-demo/ClaimDemo.lean)证明“两个自然数中的偶数相加仍是偶数”。它仅用于测试编译与公理检查，独立于研究项目；[进阶教学案例](examples.md)另用经典实分析训练量词判断，两者不是同一份证明。

| 代码名称 | 中文含义 | 类型与单位 | 在证明中的作用 |
|---|---|---|---|
| `left`、`right` | 两个任意输入数 | 自然数；无单位 | 主张的输入 |
| `leftWitness`、`rightWitness` | 两个偶数各自的一半 | 自然数；无单位 | 偶数前提提供的见证 |
| `left_even`、`right_even` | 输入等于对应见证两倍的等式 | 命题及其证明 | 展开偶数定义 |
| `halfSum` | 两数之和的一半 | 自然数；无单位 | 结论要求构造的见证 |
| `Nat`、`2` | 自然数类型、固定乘数 2 | 类型、自然数常量 | 明确取值域与偶数定义 |

代码中的存在量词要求找到一个见证；证明取两个已有见证的和，再使用乘法对加法的分配律。没有概率、样本量或实验条件。

已有 Lean 项目时，在该项目环境运行示例的绝对路径：

```bash
lake env lean /path/to/claim/assets/proof-demo/ClaimDemo.lean
```

文件末尾打印完整命题和 `#print axioms ClaimDemo.even_add_even`。验证记录保存本次实际运行结果。真实项目应固定 `lean-toolchain` 与 Mathlib 依赖，避免本机和协作者使用不同环境。

检查传递依赖中的 `sorryAx`、自定义公理及原命题对应关系。具体含义参见 [Lean 官方验证文档](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)和[公理说明](https://lean-lang.org/doc/reference/latest/Axioms/)，于 2026-09-17 核对。

## 可选接入 Prove2Me

使用 [Prove2Me 官方工作区](https://github.com/prove2me/prove2me_workspace)及其当前协议，将目标陈述、定义和证明文件连接到相应环境。Claim 的[形式证明协议](../claim/references/formal-proof.md)保持主张与证明结果的对应关系，不另造平台 API。

提交前核对目标的精确形式陈述和环境。平台返回 `PENDING` 时仍在等待；`SKETCH_ACCEPTED` 表示分解已接受但还有开放依赖；`ACCEPTED` 对应平台核对过的那个命题。具体状态以[官方提交协议](https://github.com/prove2me/prove2me_workspace/blob/main/references/prove.md)为准，2026-09-17 已重新核对。

自然语言说明应解释关键引理为什么足够，而不是逐条复述 tactic 命令。目标已证明后，还要回查论文是否使用了相同条件。上传内容和目标项目由用户决定；本地 Lean 检查可以独立完成。
